## 产品范围

服务对象是 Vue 应用开发者和排障人员。下一阶段覆盖 SDK、一个可运行的 Vue 示例、仅用于本地验收的事件接收器，以及自动化验证。完整业务流程为：安装依赖 → 配置 SDK → 接入 Vue 和路由 → 触发采集 → 在本地接收器查看事件 → 停止并释放资源。

开发基线建议采用 Vue 3 与 Vue Router 4，具体支持版本在实现时固定到依赖和锁文件，并同步到 README。已有三个 hook 的导出名称尽量保留；新增配置 API 和返回值需在实施前写明契约。当前不扩展生产数据存储、管理后台、告警平台和账号系统。

以下验收指标是本项目的开发目标，不是截图平台公布的门槛。

## 可验收需求

### R1 可安装工程与接入示例

优先级 P0。建立包元数据、明确的模块入口与内部导入、依赖约束、锁文件、构建和测试脚本。提供 Vue 示例及本地事件接收器，在 README 中给出复制即可执行的步骤。

验收：在干净目录检出后，按 README 安装和启动即可运行；示例使用对外入口导入三个 hook；触发错误、性能采集和路由跳转后，接收器均能收到对应事件。不依赖个人机器上的 alias、私有地址或未声明依赖。正式 npm 发布不属于本阶段验收条件。

### R2 可配置且互不干扰的事件上报

优先级 P0。增加上报地址、请求超时和调试开关等配置入口；未配置或配置非法时给出明确的初始化错误，不能默默向当前页面发请求。约定统一事件字段，包括事件类型、发生时间、页面地址、SDK 版本及各类事件数据。

每次发送独立管理请求，处理超时和失败，避免影响宿主业务。默认不打印事件详情。页面 URL、路由 query 和 params 应有脱敏策略；至少移除 URL 凭据和片段、默认不采集 query 与 params，显式开启时采用字段白名单。外部错误消息和堆栈提供过滤或截断入口。

验收：本地接收器成功响应时，连续发送 10 个不同事件均能被收到且不互相取消；模拟超时、网络失败和 500 响应时宿主流程仍继续，SDK 不产生未处理异常；测试数据中的 URL 凭据及未允许参数不会出现在请求载荷或默认日志中。失败重试和离线缓存留待后续设计，不承诺默认可靠投递。

### R3 完整且健壮的错误采集

优先级 P0。覆盖 JavaScript 运行错误、未处理 Promise 拒绝、Vue 组件错误，并能识别资源加载错误。保留可获得的 message、stack、文件及行列信息；不依赖固定的错误消息格式。兼容 Error、字符串、普通对象、null 等拒绝原因和缺少堆栈的情况。

修复堆栈逐帧解析与空值保护，组件实例缺失时安全降级。交互路径优先读取标准事件路径并提供回退；生成 selector 时不修改输入数组。SDK 默认保留浏览器原有错误展示行为。

验收：上述错误场景均有对应测试及示例入口；同一采集来源不因重复启动而重复发送；两帧有效堆栈均被保留，无可解析堆栈时返回空结果且不抛异常；资源错误不会再次触发采集器异常。Vue 与全局事件对同一异常的跨来源去重另行定义，不在本阶段宣称完全去重。

### R4 有限等待的性能采集

优先级 P1。对 PerformanceObserver 及各 entry type 做能力检测，区分导航性能和资源性能的来源。明确 FP、FCP、LCP、FID、DNS、TCP、TLS、TTFB 等字段的定义、单位及缺失原因；耗时保持数值类型，不以字符串或 0 混淆缺失值。

初始化后可上报已获得的数据；建议等待上限为 5 秒且可配置，达到上限时缺失指标记为 null 并附原因。无交互时不等待 FID 无限轮询。LCP 持续更新候选值，在约定的页面生命周期边界结束观测；晚到指标允许以明确的更新事件补充。

验收：在无首次输入、缺少导航条目、不支持某类 observer 的场景下，仍在配置时间内给出结果且不抛异常；多个 LCP 候选可更新最终值；导航事件与资源事件分别使用其自身条目；stop 后不再出现回调、定时轮询或新增上报。计时语义在测试用固定时间戳验证。

### R5 准确的路由停留时长

优先级 P1。在成功完成的导航上结算上一页；首次有效页面进入后开始计时，取消或失败的导航不切换计时归属。当前阶段将页面标识定义为规范化 path，同路径 query 或 params 变化不拆分停留；时长定义为实际经过时间，包含后台停留，后续可单独增加活跃时长指标。

提供注销能力；页面离开及主动停止时按约定结算一次，避免重复上报。页面离开场景使用适当的尽力发送方式，文档说明浏览器关闭时不能保证服务端接收。

验收：使用可控时钟模拟 A 页面停留 1000 ms 后成功进入 B，A 的时长为 1000 ms；首次导航不产生虚假的来源页；失败导航不提前结算；同路径参数变化不新建会话；pagehide 与 stop 相继触发不重复结算；卸载后守卫不再生效。

### R6 可停止并可重新启动的生命周期

优先级 P0，随各采集模块完成。所有浏览器监听、路由守卫、observer、计时器和请求资源均有清晰归属。重复启动不会叠加监听，重复停止安全；停止后允许重新启动。Vue 原 errorHandler 需要保留并链式调用，停止时仅在当前处理器仍由 SDK 持有时恢复，避免覆盖宿主后续设置。

验收：start → start → stop → stop → start 之后单次触发只产生一次预期采集；stop 后无残留监听和轮询；没有 window、document、navigator 或 XMLHttpRequest 的环境中，仅导入模块不抛异常，尝试启动时按文档降级或返回明确状态。

### R7 与代码一致的文档和质量验证

优先级 P1。README 补齐项目定位、支持范围、目录结构、安装、配置、三个 hook 的参数与返回值、上报载荷、完整示例、停止方式、验证命令和已知限制。修复失效图片链接，并核对 UA 元信息及 selector 输出的边界行为。

验收：每项 R1 至 R6 都能对应到自动化用例或可复现的浏览器验证步骤；单元测试覆盖异常输入、发送失败与资源释放；示例完成三条采集链路的浏览器联调。持续集成从干净环境安装、检查语法、执行测试和构建；README 命令与实际脚本一致。声明支持的浏览器需有验证记录，未验证的平台只列为限制。
